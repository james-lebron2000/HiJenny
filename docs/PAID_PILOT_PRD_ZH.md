# HiJenny 产品需求文档｜医药资产引进的首轮临床尽调
2026-11-26 · 评审稿 · 供产品、研发、医学审核和 BD 负责人共同评审。以下定价、排期、转化目标均待团队和客户验证。

## 1. 产品决策与依据

建议首版服务有近期肿瘤资产引进项目、即将召开内部评审会的药企。采购单位定为“一项资产的一轮临床尽调”。客户收到三件能继续使用的工作成果：对外可发的卖方问题清单、对内可讨论的一页决策简报、供医学和统计复查的证据底稿。预算理由是减少第一轮查数和反复确认的工时，同时让负责人看清哪些交易假设仍待补证。通过客户实际付款及第二次采购检验这个判断。

| Noah 官网能观察到的设计 | HiJenny 应怎样转化 |
|---|---|
| Research、Clinical、Medical 分别用具体工作描述价值，个人试用和企业联系有不同入口 | 首屏只讲买方 BD 的一项近期任务。访客直接打开工作样例，已有资产的负责人直接询价 |
| 企业服务说明谁进场、用谁的数据、第一周能得到什么 | 报价单列出客户提供的资料、我方审核人、交付日和卖方答复后的更新次数 |
| 可回溯来源、专家裁量、数据驻留与服务描述并列 | 在每个关键数字旁提供出处，在询价按钮旁说明资料接收方式，列清当前支持的部署条件 |
| 模拟、设计、执行、学习形成连续过程 | 展示同一个问题怎样从材料差异走到索取补件，再走到会议简报修订。保留前后两个版本供客户核查 |

官网是对其产品和服务的公开描述。它没有给出可用于推断首访付费率的数据。参考来源：[Noah AI 官网](https://www.noah.bio/)。

## 2. 购买人、使用人和触发时机

| 角色 | 典型时刻 | 本次购买要回答的问题 |
|---|---|---|
| BD 负责人／预算持有人 | 下周评审，卖方刚开放资料室 | 哪些数据影响我们是否投入下一阶段尽调？会上谁解释，何时能补齐？ |
| BD 经理／项目牵头人 | 协调临床、统计和外部顾问发第一轮问题 | 哪些问题可以合并？交给谁？我今天能发哪一版？ |
| 临床或统计审核人 | 商业材料的数字与临床资料出现差异 | 两个数字是否可比？出处、分母、截止日和评价方法能否逐项复核？ |
| 信息安全与采购 | 准备开放客户资料 | 谁可读取原件？是否调用外部模型？交付后谁负责删除并留证？ |

首轮聚焦有可读电子版临床资料、明确会议日期和具名审核人的项目。客户只有路演 PPT 时，先交资料缺口与索件范围，由客户决定是否补齐后启动完整试点。跨治疗领域覆盖、组合估值和成交预测留待后续需求验证。

## 3. 从现有产品到客户首屏

现有工作台从 Projects 和选择项目开始，适合已有项目的分析人员。仓库已提供 Asset 360、原文定位、问题导出、问题级卖方答复、复核和发布 Decision Brief。公开样例有 13 份文件、284 页、136 条证据、11 项活跃发现和 6 个卖方问题，均来自合成资料。当前决策简报同时把 ORR 42% 列在支持项、把 ORR 差异列在重大风险。建议优先解决这个阅读风险：即使 42% 能定位到原文，冲突未解释时，负责人也必须在数字旁看见待核状态。

**首页文案建议**

> 下周要评审这项引进资产，先弄清哪些临床数字还要问卖方。  
> HiJenny 核对卖方临床资料，帮 BD 和医学团队准备有出处的问题清单与一页会议简报。  
> ［查看 2 分钟尽调样例］　［获取单资产试点报价］

按钮下直接展示一张可交互样例卡，持续标识“合成案例 · ASD-101”。左侧列“临床研究报告第 10 页：ORR 42.0%”与“商业预测材料：48.4%”，各自链接到对应原文。右侧显示“商业预测采用哪个分析集？请提供两个数字对应的缓解人数、分母、评价者和数据截止日。”底部显示会议处理意见“差异待核实，暂缓沿用该疗效假设”。后者是建议的演示措辞，须由审核人确认。界面不得将跨文件差异直接解释为疗效优劣。

**两分钟演示路径**：打开合成样例 → 点两个数字核对原页 → 看审核后的卖方问题 → 切换至预置的合成答复 → 查看医学审核后简报哪一句发生了变化 → 下载带样例标记的简报。访客也可直接申请报价；已有账号用户保留工作台入口。首页默认中文，文件原文保留原语言。

## 4. 功能范围与验收

| 优先级 | 需求及复用点 | 可验收行为 |
|---|---|---|
| P0 | 公开只读样例与工作台独立入口，复用冻结的样例证据、原页和导出件 | 手机和桌面均可免登录走完演示；样例链接只能读取公开快照；无资料时显示缺项；公开样例与客户项目使用独立数据目录 |
| P0 | 决策简报把“来源已核对”和“交易假设可采用”分开展示；复用 finding、证据与 BD 复核 | ORR 有未结差异时，屏幕与导出件在数字旁同时显示“待核实”、原因、责任人和证据；仅有卖方解释时仍显示待补证；审核后记录判断及依据 |
| P0 | 分开生成对外问题单与对内会议简报；利用现有 Excel 与报告导出 | 对外版按允许字段生成，仅含问题编号、问题、索取材料和约定期限；测试样例中的内部判断、谈判假设及私有附件链接均不会出现在外发文件。内部版列出处、未结问题、下一步及签核人 |
| P0 | 把现有卖方复核变为可重演的修订记录 | 一次补件关联问题、来源和日期。复核人可选“已解释／部分解释／仍待补证”。重复发布同一版保持一条记录；旧简报可读取，新简报显示版本、变化原因和审核人 |
| P0 | 报价及交付受理 | 表单仅收工作邮箱、阶段、页数区间、预计评审日、部署偏好。提交后返回受理编号、联系人和下一步；重复提交可识别；预约页不接收原始资料。BD 可从受理记录追踪到正式报价与实付 |
| P0 | 真实资料准入与异常处理 | 交付负责人和客户确认环境、访问名单、用途、保留期限及删除方式后接收资料。入库核对文件清单；扫描页、解析失败、缺原件单列，由专家补录或标为未覆盖，并在简报中披露 |
| P1 | 可比资产增强，复用既有问题级可比资产记录 | 只在客户问题需要时加入有来源和日期的参照；列示人群、线次、终点与评价差异。资料不足时显示不可直接比较，不计算跨试验疗效排名 |
| P1 | 同一买方的第二个资产复用 | 在客户授权范围内复用其问题模板和审核偏好；新项目的来源与判断重新建立。跨客户复用仅限通用模板 |

生产依赖：本地单用户 MVP 尚缺登录、项目成员权限和静态加密。公开演示应为只读合成快照。多人在线处理真实原件前，按已有生产路线完成身份、授权、加密及审计验收；试点如选客户自有隔离环境，逐项记录该环境实际提供的控制及负责人，再决定可接资料范围。客户品牌、真实案例展示权和模型训练授权各自单独约定。

## 5. 试点报价与交付运营

沿用现有客户一页纸的 ¥9,800–29,800／资产区间。建议首先测试一个容易解释的中间报价 **¥19,800／资产**。这是待验证的报价，不是历史订单。报价前清点可解析页数、资产数量、语言和审核工作量，记录分析、医学复核、交付与返工工时。若毛利无法支撑专家审核，应调整范围或价格。

| 建议报价项目 | 客户得到什么 |
|---|---|
| 标准试点 ¥19,800 | 1 项肿瘤资产、最多 1,000 页可读电子资料；1 次启动会、1 轮临床与统计问题复核、3 类交付件、1 次结果会；首轮交付后 10 个工作日内含 1 批卖方补件复核 |
| 交付窗口 | 以资料清单、审核范围和运行环境确认日为 D0。D1 交付目录及不可读项；D2–D3 初稿与医学／统计核查；目标 D3–D5 交首轮签核版。等待卖方答复另计 |
| 变更与验收 | 超页数、多资产、扫描件密集或新增领域先书面改价／调整日期。客户指定审核人逐项验收文件、证据定位和未结项；引文错误由交付团队修正并重新出版本 |
| 再采购 | 结果会上记录实际节约工时、被客户采用的问题、重复需求和预算人。出现第二个付费资产后再讨论年度项目包 |

采购成功以实际付款或客户采购系统可核实的正式订单记录，分别记账。邮件回复、预约演示、意向书各自单列。

## 6. 验证计划与决策标准

以下数字供首轮评审选择。小样本逐案记录原因，暂不据此推断总体转化率。

| 验证问题 | 方法、分母与拟定决策线 |
|---|---|
| 第一眼能否看懂？ | 邀请 8 名符合画像的 BD／医学人员，各自首次浏览 30 秒后关屏。至少 6 人能说出使用场景、一项可带走的成果及下一步。若只记得“AI 查文献”，重写首屏 |
| 是否值得付钱？ | 接触 10 家有近期资产、明确负责人和会议窗口的独立机构，记录样例浏览、演示、正式报价、订单、实付及流失原因。目标 30 天内至少 2 家实付；只有询价时先访谈预算人，定位报价、可信度或时机障碍 |
| 交付质量是否合格？ | 按项目预先冻结关键字段与双人独立标注，分歧交第三人裁定。沿用目标：关键字段召回≥95%（命中／应提取），引用准确率≥99%（定位且语义支持／核查引用），A 类直接矛盾误报≤2 条／包。签核版重大结论逐条核查；发现无依据的重大结论即退回修订 |
| 有多少人工收益？ | 在同一包、同一范围上记录人工基准和工具辅助下从接收到签核的人员小时，计入纠错、补录和专家复核。优先用独立人员做配对评估；只有历史估算时单列。试点沿用节约≥50%的目标，报告每包起止点与绝对工时 |
| 客户会再次购买吗？ | 首批交付后 60 天记录有第二项合适资产的客户数、收到二次报价数、实付数。若复购为零，区分资产尚未出现、交付无效和采购受阻，再决定是否开发年度版 |

页面事件最小集为样例打开、原页打开、样例简报下载、询价提交。销售侧记录资格、报价、订单和回款，用受理编号衔接。公开分析事件仅记事件、时间、匿名会话和样例版本，避免记录客户资产名、原文、邮箱或上传内容。

## 7. 排期与评审决议

| 时间（建议） | 负责人 | 输出与放行条件 |
|---|---|---|
| 第 1 周 | 产品、BD、医学 | 冻结 ORR 演示材料和两版简报；完成 8 人理解测试；确认报价假设和签核责任 |
| 第 2 周 | 前端、后端、QA | 发布只读样例、双 CTA、询价受理；以合成资料验证引用跳转、未结状态、外发字段及版本恢复 |
| 第 3–4 周 | BD、交付、客户安全负责人 | 向合格客户正式报价，完成环境核验、范围确认和首轮付费交付；遇权限或质量缺口时仅演示或转入整改 |
| 第 5–6 周 | 产品、医学、财务 | 核对付款、逐包质量、工时与交付毛利；根据失单和返工原因排下一轮开发优先级 |

本次评审需决定三件事：谁负责最终临床／统计签核，¥19,800 试点包含多少专家工时，首位客户在哪个获批环境交资料。三项确认后才能把试点报价与交付日期写入对客承诺。
