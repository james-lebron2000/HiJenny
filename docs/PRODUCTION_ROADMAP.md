# HiJenny 真实场景落地优化路线图

> 基于当前 MVP（v0.1，已跑通合成资料包端到端）与代码审计，给出从「演示可用」到
> 「真实客户可付费试点」的优先级、工程改动与验收标准。
> 结论先行：**先补可信度与安全/工作流，再谈规模与多 Agent 扩展。**

---

## 0. 当前基线：哪些已经够用，哪些是真实短板

**已经具备（不要在试点前推翻）**

- Evidence-first 数据模型：Document → Page → Evidence → Finding → Question，逐字引用 + 页码可追溯。
- 六维可比性门控：A/B/C/U 分类，避免把不同 cutoff/人群误判为矛盾。
- 确定性工作流：解析→抽取→逐字校验→一致性→缺口→问题→报告，幂等可重跑。
- 离线默认 + 可选 LLM 适配层；注入文本被当作数据并标记。
- 完整交付物：Decision Brief + 报告（MD/DOCX）+ 6-Sheet Excel + 审核 UI。
- 评测与回归框架：合成语料 36/36 事实、findings P/R/F1 100%、引用 100%、174 tests。

**真实场景的短板（代码审计确认）**

| 维度 | 现状 | 真实客户会问什么 |
|---|---|---|
| 真实资料泛化 | 抽取规则针对英文 CSR/IB/SAP 表述调优；无 OCR；复杂表格/图表会漏 | “我们的 CSR 是扫描版/排版不同/中英混排，能提准吗？” |
| 质量证明 | 仅合成语料评测；无双人裁定真实资料 benchmark | “给我看你们在真实项目上的准确率和误报率。” |
| 审核工作流 | 只有基础编辑/审计事件；无分派、评论、审批、版本 diff、批量操作 | “5 个人怎么协作？谁签字？改了什么怎么追踪？” |
| 安全合规 | 无登录/SSO/RBAC/加密/审计导出；单机 SQLite + 本地文件 | “数据放在哪？谁能看？模型会不会留存？能私有化吗？” |
| 工程规模化 | 单进程线程、SQLite、无队列/对象存储/监控/备份/Docker | “1,600 页资料包并发 10 个项目会不会崩？成本多少？” |
| 交付运营 | 无客户交付 SOP、模板分级、SLA、问题库 | “3–5 天怎么保证交付质量？谁负责医学审核？” |
| 产品边界 | 临床为主；CMC/注册/IP 仅占位 | “能不能一起看 CMC 和专利？”（先答：V2，不硬做） |

## 1. 落地三道门槛（Gate）

真实客户不会因为“Demo 很酷”付费，只会因为这三件事：

### G1 可信（Trust）
- 真实资料上关键字段抽取召回 **≥95%**；引用准确率 **≥99%**；
- Type A 矛盾误报 **≤2 条/包**，且每条可解释；
- 报告里 **0 条**无法在原文定位的结论；
- 双人独立裁定 + 一致性统计（Cohen's κ 记录）。

### G2 可用（Workflow）
- 3–5 个工作日完成一个资料包的“证据包 + 问题清单 + DD memo”；
- 支持审核分派、评论、批量处理、签核、v1→v2 版本对比；
- 人工修改可被记录并反哺规则/模型（质量飞轮）。

### G3 合规（Security）
- SSO/RBAC/项目 ACL、传输与静态加密、审计导出；
- 默认私有化/VPC 部署，数据不出客户边界；LLM 网关可关、可换、可审计；
- DPA/子处理商清单、数据保留与删除策略、渗透测试与漏洞管理。

## 2. P0（0–6 周）：试点前的硬门槛

按“影响 × 必要性”排序，前 6 项不做完不建议接真实客户资料。

### P0-1 真实资料包 + 双人裁定 Benchmark（最优先）
- 取 **3 个真实脱敏资料包**（最好来自 2 家不同卖方/ CRO 排版），覆盖扫描版、复杂表格、中英混排。
- 双人独立标注：字段级事实、A/B/C 问题、缺口、期望问题；分歧由第三人/a third senior reviewer 裁定，记录 κ。
- 建立错误分类：漏抽、错抽、维度错配、误报 Type A、引用错页、表述不可用。
- 交付物：`eval/real_benchmark/` + scorecard；每次发版跑回归。
- **验收**：真实包上字段召回 ≥95%、引用 ≥99%、Type A 误报 ≤2/包；分数下降则阻塞发版。

### P0-2 解析鲁棒性（决定 50% 的真实体验）
- OCR fallback（PaddleOCR/Tesseract，按页判定扫描件）；保留“低质量页”提示与人工复核入口。
- 表格结构升级：Docling/pdfplumber 结构化表格，保留行/列/单元格坐标；合并单元格、跨页表、脚注。
- 章节感知：按 CSR 目录/标题切 section，把事实抽取限制在“该字段应在的章节”（避免全文正则误抽）。
- 中文/中英混排：至少支持中文页文本解析与常见字段；抽取规则按语言路由，英文规则不硬套中文。
- 文件形态：DOCX 修订痕迹、PPTX 备注、XLSX 公式/多 Sheet、加密/损坏文件的明确错误。
- **验收**：3 个真实包解析成功率 100%（允许页级失败但必须可见）；扫描页识别率 ≥95%；表格字段召回显著提升。

### P0-3 抽取质量与“可解释的置信度”
- 真实资料默认 **hybrid**：规则先跑，LLM 仅在缺失/低置信时补，且必须回填 page + verbatim quote。
- 置信度校准：区分“规则高置信/LLM 中置信/人工确认”；报告与 UI 显示证据等级。
- 实体/试验归并：跨文件同一试验、同一资产、同一队列的 canonical 化（NCT/内部编号/臂/剂量）。
- 增加真实尽调高频字段：既往治疗线数、基线特征、剂量调整、亚组、OS 成熟度、方案偏离、统计方法细节。
- 纠错采集：审核人修正（值/维度/引用）写回 `corrections` 表，作为规则回归与 active learning 数据。
- **验收**：真实包上字段召回 ≥95%，引用 ≥99%；同一字段不因 LLM 引入新的不可比记录。

### P0-4 审核工作流（从“能看”到“能协作”）
- 角色：BD / Clinical / Safety / Biostat / Regulatory / Admin；项目级成员与权限。
- 分派与状态：assignee、due date、comment、@mention、批量改优先级/状态、review queue。
- 签核：Finding/Question 的 approve/reject + 签署人 + 时间戳；导出带审核状态的报告。
- 版本对比：v1→v2 文档/证据/发现 diff（“哪些数字变了、哪些问题解决了、哪些新增”）。
- **验收**：3 人并行审核一个包 ≤2 天；所有对外问题 100% 有签核记录；版本 diff 可解释。

### P0-5 安全与部署基线
- 认证：OIDC/SSO（Azure AD/Google/Okta），会话与登出；RBAC + 项目 ACL。
- 加密：TLS；数据库/对象存储静态加密（KMS）；导出文件签名 URL。
- 部署：Docker Compose（pilot）/ Helm（企业）；默认 VPC 或私有化；数据不出境选项。
- LLM 网关：统一出口、可关闭、可切换供应商、请求脱敏（可选）、不训练不留存条款、成本上限。
- 注入加固：模式库 + 输出约束 + 禁止文档触发工具/网络；可疑文本隔离与告警。
- 审计：登录、查看、导出、修改、模型调用全链路审计；审计日志可导出。
- **验收**：客户安全问卷可回答（SSO/加密/隔离/保留/子处理商）；内部渗透测试无高危。

### P0-6 工程规模化基线
- PostgreSQL 替换 SQLite（Alembic 迁移）；S3/MinIO 存原始文件与导出；Redis + RQ/Celery 跑解析/抽取任务。
- 任务：并发限制、重试、幂等、取消、死信、进度（SSE/WebSocket）。
- 可观测性：OpenTelemetry（trace/run 级别）、结构化日志、任务耗时/失败率/成本仪表盘。
- 备份/恢复：DB 与对象存储每日备份 + 恢复演练。
- **验收**：10 个并发项目、单包 1,600 页压测通过；p95 处理时间与单页成本可计量。

### P0-7 交付模板与运营 SOP
- 报告模板：标准版/精简版/客户品牌版；中英双语；Decision Brief 固定结构。
- 交付物：Evidence Matrix、Question List、DD Memo、风险清单、版本历史、审核记录。
- SOP：资料完整性预检（缺哪些文件先问）、3–5 天排期、医学审核 SLA、问题库与答复跟踪。
- **验收**：一份真实包从上传到客户可发版本 ≤5 个工作日；返工率可统计。

## 3. P1（6–12 周）：可复制的付费试点

| 方向 | 要做的事 | 价值 |
|---|---|---|
| 多租户 | Organization、邀请、角色、用量与配额、账单维度 | 从单客户项目走向 SaaS |
| 规则库 | 按适应症/阶段/交易类型分包；红黄绿灯风险评分；问题模板库 | 可复制、可解释、可售卖 |
| 决策支持 | Risk Register 导出、DD Memo 模板、IC 版 Decision Brief（仍不自动 Go/No-Go） | 贴近真实决策 |
| 集成 | VDR 连接（Intralinks/Box/Datasite）、邮件/Teams 通知、API/Webhook | 嵌入客户流程 |
| 质量飞轮 | 纠错数据 → 错误分类 → 规则/LLM 迭代 → 金标准回归；漂移监控 | 越用越准 |
| 安全认证 | SOC2 Type I / ISO27001 准备、DPIA、渗透测试、子处理商清单 | 企业采购门槛 |
| 成本 | 缓存、批处理、页级成本核算、可选本地模型 | 毛利率可控 |

**P1 验收**：≥3 家付费试点、≥2 家续费/转订阅；问题清单可直接采用率 ≥70%；人工工时节约 ≥50%；单项目成本可核算。

## 4. P2（3–6 个月）：规模化与平台化

- 私有化/混合部署产品化（BYOK、离线模型、审计导出）。
- CMC / 注册 / IP 轻量 Agent（先 checklist + 文档定位，不做自动法律结论）。
- 跨资产 Benchmark、组合视图、交易漏斗；与估值/风险系统对接。
- 主动学习/受限微调（客户授权数据），提升格式泛化。
- 生态：CRO/咨询合作伙伴、白标交付。

## 6. 质量飞轮（决定长期壁垒）

```
真实项目审核修改
   → 结构化纠错标签（字段/值/维度/引用/问题表述）
   → 错误分类（漏抽/错抽/误报/不可比/引用错）
   → 规则 & LLM prompt/grounding 改进
   → 金标准回归集（按文档类型/语言/卖方格式）
   → 发版门禁（召回/引用/误报/问题可用率）
   → 下一个真实项目
```

关键工程点：
- 审核 UI 的“修改”必须落成**可训练标签**（而不只是 review_event 的 before/after）。
- 每次发版自动跑真实 benchmark + 合成回归；指标下降阻塞发布。
- 记录“人工确认/驳回”的原因，用于问题模板与风险评分校准。

## 7. 真实数据评测方案（试点前完成）

1. 3 个真实脱敏包，覆盖：英文 CSR、扫描版 PDF、中英混排/不同排版。
2. 双人独立标注 + 分歧裁定；报告 κ 与分歧类型。
3. 预注册指标与门禁，不做事后调参。
4. 指标：字段召回/精度、引用准确率、Type A 精确率/召回率、缺口召回、问题可用率（评审 1–5 分）、端到端工时（含人工复核）、单页成本。
5. 留出集：至少 1 个包不参与规则调优，只用于最终验收。

## 8. 安全与合规清单（客户问卷可答）

- 身份：SSO/OIDC、MFA、会话管理、离职回收。
- 权限：org/project ACL、最小权限、导出审批。
- 数据：TLS、静态加密、KMS/密钥轮换、备份加密、保留/删除、数据驻留。
- 模型：供应商 DPA、不训练/不留存、区域端点、私有化选项、请求脱敏、成本上限、调用审计。
- 注入：文档隔离、禁止工具调用、模式检测、可疑内容告警、输出约束。
- 合规：DPA、子处理商清单、DPIA、SOC2/ISO27001 路线、AI Act/医疗器械边界评估（决策支持而非诊断）、责任限制与免责声明。
- 运维：漏洞管理、渗透测试、事件响应、审计导出、灾备演练。

## 9. 商业化落地建议

- **首个 ICP**：中国/亚洲 Biotech 或 Pharma 的 BD/License-in 团队；先做肿瘤临床 DD。
- **首个产品形态**：3–5 天“AI + 专家复核”项目制交付，核心交付物是 **Seller Question List + Evidence Matrix + DD Memo**（报告是载体，不是卖点）。
- **定价**：¥9,800–29,800/项目（试点可更低换案例与评测数据）；验证后转订阅/企业版。
- **不要卖“纯 AI 报告”**：明确 AI 产出 vs 专家复核 vs 咨询增值；按项目核算毛利。
- **扩张路径**：临床 DD → CMC/注册/IP 模块 → 组合/交易智能平台。
- **销售材料**：真实（脱敏）样例报告、benchmark 数据、安全问卷答案、客户推荐语。

## 12. 明确不要做（避免拖慢验证）

1. 不做自动 Go/No-Go、不做自动估值/条款。
2. 不做“通用文档聊天”，不为 Demo 增加炫技交互。
3. 不在没有真实标注数据前微调模型。
4. 不先做 CMC/IP 深度自动化（先临床验证付费意愿）。
5. 不做多 Agent 自由辩论/知识图谱等重架构。
6. 不为签单牺牲安全（真实 VDR 数据不进未授权环境）。
7. 不承诺“任意资料 95%”——只承诺在约定文档类型/语言/评测范围内的指标。
